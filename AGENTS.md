# Agent guidelines

Project: `ah-my-openresearch` (alias `amore`).

Guidelines for AI agents (Claude Code / Codex / OpenCode) working on this repository.

## Stack

- **Runtime:** Bun
- **Language:** TypeScript (strict)
- **Linter/Formatter:** Biome (single tool)
- **Schema:** Zod
- **Plugin target:** OpenCode (`@opencode-ai/plugin`, `@opencode-ai/sdk`) — TBD installed in Phase 0
- **MCP SDK:** `@modelcontextprotocol/sdk` — TBD installed in Phase 3

## Commands

| Command | What |
|---|---|
| `bun install` | Install deps |
| `bun run build` | Build to `dist/` (TODO Phase 0) |
| `bun run typecheck` | TypeScript type check |
| `bun test` | Run tests |
| `bun run check` | Biome lint + format + organize imports |
| `bun run check:ci` | Biome check without write (CI mode) |

## Code style

- Files: kebab-case (e.g. `claim-extract`, not `claimExtract`)
- Variables/functions: camelCase
- Classes/interfaces/types: PascalCase
- Constants: SCREAMING_SNAKE_CASE
- Quotes: single
- Trailing commas: always
- Line width: 80

## Project structure

See `codemap.md` for the architecture cascade.

Per directory:

- `src/agents/<name>.ts` — agent factory `create<Name>Agent(model, customPrompt?, customAppendPrompt?)` returning `AgentDefinition`. Each persona has a fixed default prompt and exposes prompt override / append for advanced users. Mirror `src/agents/librarian.ts` for shape.
- `src/skills/<name>/SKILL.md` — markdown skill: YAML frontmatter (`name`, `description`) + body with usage instructions. Always reference the source (ARIS / claude-octopus / academic-research-skills / GAP) at the bottom.
- `src/mcp/<name>.ts` — MCP server registration. Upstream URL in header comment.
- `src/config/` — Zod schema is source of truth; JSON schema is generated by `scripts/generate-schema.ts`.
- `src/cli/` — CLI commands. Each subcommand in its own file.
- `src/hooks/<name>/` — OpenCode lifecycle hooks (pre-write enforces drafts-only, etc.).
- `src/lab/` — per-project lab contract: directory layout, edges.jsonl, claim-schema validators.

## Design source

`design/Product Design.md` is canonical for product decisions. Before any non-trivial change, read the relevant section and reference the decision ID (D1-D11). Skill list is in `design/Skill Catalog.md`.

If a design decision is needed, do not invent — surface it. Open items at time of scaffold: D4 (name), D5 (distribution), D7 (approval surface), D10 (auto-flag), D11 (file conventions).

## Convention: STUB markers

Every stub file has `(STUB)` or `TODO:` markers. When implementing, remove the marker only when the implementation matches design intent. Don't silently delete `TODO:` lines without resolving them.

## Don't

- Don't break the cascade order from `codemap.md` (e.g. don't wire CLI install before config schema is real).
- Don't add deps not justified by design (every dep should map to a section in `design/Product Design.md`).
- Don't write outside `<project>/lab/drafts/` (or `lab/critique/`) from agents (this will be enforced by `src/hooks/pre-write-drafts-only/` once it exists).
- Don't translate `design/*` docs without keeping the original (they're historical record).
